## 問題

- 預期行為：交接系統應能記錄每名工作者目前使用的電腦，以及該電腦上每個相關 Git repository 的本機絕對路徑。接手者應依「目前工作者＋目前電腦」取得正確路徑，並用 Git remote 驗證 repository 身分。

- 影響：接手者可能找不到成果、誤判成果不存在、在錯誤 clone 上修改或測試，或把交接 repository 與正式成果 repository 的 Git 狀態混為一談。若進一步執行還原、提交或刪除，可能造成錯誤工作樹的資料損失。

## 建議處理

- 臨時處理：允許員工表在每名員工下保存多筆工作環境，每筆至少包含使用者自訂電腦名稱、可取得的主機名稱、repository 邏輯名稱、本機絕對路徑、Git remote 與最後驗證時間；未知欄位明確寫 `未知`。
- 制度／流程改善：
  1. 在 schema 與 manifest 中建立正式的工作環境權威來源，可擴充 `20_員工表.md`，或新增例如 `21_工作環境表.md` 的獨立現役資料檔。
  2. 使用「員工代號＋環境 ID」作索引，允許一名員工有多台電腦，也允許多名員工各自擁有不同路徑。
  3. 成果位置以 repository 邏輯名稱及 Git remote 作穩定識別；絕對路徑只放在環境映射，不在 `10` 保存唯一全域路徑。
  4. 接手或同一工作者換電腦時，先辨識或詢問目前環境，再檢查路徑存在、repository root 與 remote 相符；不相符時停止寫入，不沿用其他電腦的路徑。
  5. 正式交接最低檢查加入「目前環境的成果路徑與 remote 已驗證」。
- 驗證方式：建立兩名員工、兩台測試電腦與至少兩個 repository，讓各電腦使用不同 clone 路徑；分別執行接手、換電腦續作及交接。確認每次只解析到目前環境的路徑，且 remote 不相符時會停止，不會改寫其他環境紀錄。
- 可能副作用：增加少量接手欄位與維護成本；主機名稱及絕對路徑可能涉及環境隱私，因此應允許使用者自訂環境名稱、遮蔽不必要資訊，且不保存帳密、Token 或個人目錄中不必要的細節。舊版資料升級時也需允許路徑為未知。
