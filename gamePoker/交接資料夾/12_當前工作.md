## 新一輪整體檢查發現

- Poker 前端宣稱 WebSocket 斷線後改用輪詢，但後端 close 會呼叫 `leave()` 清除 token；正常離場也可能由 close 與 DELETE 重複離場。
- Poker WebSocket 只送 `connected`，沒有狀態廣播；實際同步仍完全依賴每 800 ms REST 輪詢。
- 正式 Poker 頁面保留獨立加入按鈕，但非平台流程沒有提供後端必須的 JWT／modeId／Lobby Room 契約。
- Poker／Tjpoker Service 的所有房間共用 singleton 方法的 `synchronized` 全域鎖。
- GameDataInitializer 只新增缺少資料，不同步既有 path、enabled 與人數設定；GameMode 也缺少 `(gameId, modeCode)` DB unique constraint。
- Game／Mode 可被刪除，但 Lobby Room 與 Board TeamPost 只是保存 ID 且沒有 DB 外鍵，可能留下孤兒資料。
- Board 保存 platformUserId，呼叫 Poker 時卻傳 Member.id；兩條 Poker 入口使用不同 ID 命名空間。
- Board 隊長／會員檢查信任 request 提供的 ID，TeamPost／Comment 刪除另缺所有權檢查。
- Quiz 可只交一題或重複題目取得 100 分，沒有伺服器考卷／時間 session，排行榜 username 也由 request 指定。
- 舊 Poker Game 仍有跨房間 static 狀態；RuleService 另留一套未使用且不同的洗牌實作。
- Chat 主 iframe 預設載入停用的 `tjpoker` 測試入口，不是正式 Lobby／JWT Poker。
- Quiz `/exam` 直接序列化 `Option.isCorrect`，玩家交卷前可看到正解。
- Quiz 題庫新增／修改／刪除落入全域 `permitAll`；富文字未清理即保存並放入 `innerHTML`。
- Lobby 建房可由 request 的 `playerCount` 覆寫 GameMode max，更新房間也可直接替換 modeId／maxPlayers，未核對 mode 所屬 game、enabled 或 min／max。
- Board 四個 entity 使用 deprecated 且 marked for removal 的 Hibernate `GenericGenerator`。
- 前端各頁各自固定 `http://<hostname>:8080`，沒有共同 API 環境設定；HTTPS 部署會有 mixed content 風險。
- 其餘已知的 Lobby／Poker 生命週期、Chat 透明遮擋、安全授權、CORS、POM、Vite 多頁 build 與測試 DB 隔離問題已重新核對並合併在跨組文件。
