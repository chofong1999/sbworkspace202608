# 圖文筆記驗證與回歸

- 方法版本：`1`
- 適用規則：`SBIMG-RULE-001～012`
- 參考經驗：`JavaWeb舊系統的基本QA、樣本先行、重複錯誤回歸與使用者入口分流。`

## 一、本機基本檢查

每篇本輪修改的圖文筆記至少檢查：

- Markdown可用UTF-8讀取且沒有replacement character。
- 圖片引用指向存在、非空且可解析的檔案。
- 替代文字非空；圖說存在並說明圖片用途。
- 內部連結可解析；程式碼圍欄成對。
- 候選、失敗圖與內部QA未混入正式文章入口。

## 二、視覺檢查

- 在預定觀看尺寸檢查關鍵文字、URL、結果與標記。
- 裁切圖與原圖對照，確認沒有遺失必要上下文。
- 標記與說明一一對應，沒有遮擋、交錯及無功能裝飾。
- 圖片與前後文一致，不使用一張圖證明它實際無法證明的結論。

## 三、GitHub實際渲染

只有內容已Push後，才可執行GitHub驗證：

1. 開啟正式GitHub Markdown頁面。
2. 確認圖片、相對路徑、章節連結與Mermaid實際顯示。
3. 檢查圖片在頁面寬度下仍可讀。
4. 遠端缺檔或大小寫錯誤時，修正並重新Push後重驗。

本機成功不能寫成GitHub已驗證；未Push時狀態保持`未驗證`。

## 四、新樣式與批次

1. 新裁切、標記或共用版型先做1～3張代表樣本。
2. 記錄唯一允許不同的項目，其餘內容與輸出條件保持一致。
3. 使用者確認時只登錄明示範圍。
4. 未確認前不套用全章或全部章節。

## 五、錯誤回歸

新缺陷先分辨：

- 既有規則未執行：修正執行或驗證閘門，不重複新增同義規則。
- 先前未涵蓋的新問題：補充工作規格、方法及可重跑案例。

常見回歸案例：

- REG-SB-01：原圖被覆寫或衍生圖無法追溯。
- REG-SB-02：裁切後失去URL、錯誤訊息或成功結果上下文。
- REG-SB-03：標記遮住文字、交錯或沒有新增資訊。
- REG-SB-04：高度重複的圖片被機械加入文章。
- REG-SB-05：替代文字或圖說缺失、只重複檔名。
- REG-SB-06：本機通過被誤寫成GitHub遠端已通過。
- REG-SB-07：自行補拍拿錯專案或未評估資料副作用。
- REG-SB-08：JSP專用分色規格被誤套到Spring Boot圖片。

修正完成前需保存：問題、根因、成果修正、規格／方法更新、影響範圍及回歸結果。
