# 按需：作圖系統更新

> 本流程只更新通用作圖系統，不等同於更新某份工作的視覺規格。未提供新版系統套件時不得執行。

## 1. 更新前

1. 讀新舊`module_manifest.json`，確認模組代號相同。
2. 確認新版相容性、入口文件與現役檔案清單。
3. 將舊檔分為：
   - 系統制度檔：由新版取代。
   - 工作資料檔：`10`至`13`、`20`至`23`、`30`、`40_工作規格`、`50_工作方法`及內部歷史，按新版格式轉換。
   - 圖片成果與來源：原地保留，不因系統更新重做或搬移。
   - 臨時導入資料：只作遷移輸入，完成後標示已吸收、引用、取代或待處理。
   - 未知檔案：列入待核對，不混入新版現役制度區。
4. 現有工作若正在寫入圖片，先停止更新；不得同時修改成果及系統。

## 2. 建立新版

1. 在獨立暫存資料夾建立新版，不直接覆蓋現役系統。
2. 使用新版manifest列出的制度檔，不搬入被取代的舊制度檔；檔名不同但控制角色相同也視為被取代。
3. 轉換工作資料，保留工作代號、工作規格來源、工作方法、樣板、候選、驗證方法、紀錄及成果引用。
4. 依新版欄位所有權重建現況：
   - `00`只保存系統與工作身分。
   - `11`唯一負責目前視覺規格版本。
   - `12`唯一負責階段、圖片／批次、批次權限及下一步。
   - `23`由新版通用規則及目前有效的`11`、`40`、`50`與`13`來源重建；不得直接沿用舊索引。
   - `module_status.json`依manifest、`00`與`12`重新產生，是供其他系統讀取的衍生介面。
5. 舊版資料夾保持原樣；新版完成前仍由舊版負責。
6. 不把舊制度文件複製進新版`90_內部歷史`；舊版資料夾本身就是完整備查來源。

## 3. 殘留與一致性檢查

更新完成前確認：

- 實際現役檔案與新版manifest完全相符。
- 沒有兩份入口、兩份通用流程或同功能的新舊制度檔。
- 沒有現役舊狀態名稱、舊指令、舊路徑或已淘汰引用；歷史原文不算現役殘留。
- 系統版本在manifest、`00`、`01`至`03`及使用者說明一致。
- `00`沒有視覺規格、樣板、當前圖片、階段或批次權限的鏡像。
- 工作代號、視覺規格版本、樣板版本、候選、驗證方法及圖片紀錄沒有被重設。
- 工作規格來源、權威程度、管理方式、版本與最近同步狀態沒有遺失。
- `作圖系統`與圖片成果根目錄分開；未修改成果沒有被搬移、重驗或重建。
- `module_status.json`的模組版本與manifest一致、身分與`00`一致、工作現況與`12`一致。
- `23`只引用現行規則與回歸來源，沒有從歷史紀錄推定現行規則。
- 候選與正式規則仍分開。
- 技術QA與使用者確認仍分開。
- 使用者成果及來源沒有被重新驗收、重算或搬移。
- 未結案修正只從舊版當前`12`或使用者目前明確指示轉換；不得從`30`、內部歷史、舊失敗QA或回饋文件推定為活動問題。

任何一項失敗時，新版保持暫存，不切換正式名稱。

額外檔案若是工作附件且仍被`10`至`13`引用，可以原樣保留；無法判定或疑似舊制度檔時留在舊版，不搬入新版現役區。

## 4. 切換

1. 完成新版檢查後，將舊版改名為`舊版_已取代_禁止使用`。
2. 將新版切換為正式作圖系統位置。
   - 不建立ZIP或額外完整複本；舊版資料夾本身就是可回復備查來源。
3. 在新版`30_製作與QA紀錄.md`追加一筆系統更新事件，只記版本、轉換結果及未處理事項，不重寫圖片歷史。
4. 若第二步失敗，立即恢復舊版正式名稱，不留下兩份可同時使用的系統。

## 5. 從0.4升級至0.5的資料規則

- 保留工作代號、視覺規格、樣板、候選、驗證方法、`40`、`50`、QA／歷史紀錄、成果位置與交接協作資訊。
- 依0.5格式補上來源身分欄位；既有工作命名規則優先，不批次改名歷史成果。
- 只轉換舊版`12`中明列仍未解決的問題；已結案歷史不重新成為待辦。
- `23_規則與回歸索引.tsv`必須重建，不複製舊索引或把回饋文件當成規則。
- 不因升級移動、重命名、重驗、重建或計算圖片成果雜湊。
- 完成後舊資料夾改名並加上禁止使用標示；不另做ZIP備份。

## 6. 舊容器與正式同層部署

若舊版把系統、規格、方法與圖片成果包在同一容器：

1. 先在暫存位置建立新版`作圖系統`。
2. 工作規格轉入`40`或建立外部引用；工作方法轉入`50`。
3. 圖片成果只在使用者已確認正式成果根目錄時移動；否則原地保留並更新引用。
4. 臨時導入資料完成分類後標示已吸收、引用或取代。
5. 完成後保留舊容器並標示`舊版_已取代_禁止使用`；使用者另行決定何時刪除。
6. 正式入口只能有一個作圖系統與一個成果根目錄。

## 7. 未來作為外掛時

若由AI工作記憶與交接平台2.x管理外掛，主平台負責安裝、相容性與名稱切換；本流程仍負責本模組內的工作資料轉換及殘留檢查。外掛不得自行修改核心交接制度或其他外掛，但可經主平台授權同步本模組的工作摘要。
