# 使用者：制度與使用說明

- 目前系統版本：`0.5`

## 這套系統做什麼

這套系統讓AI延續一份圖片工作的規格、樣板、候選方案、製作方法與品質標準，避免每張圖重新溝通，或後續成果大幅偏離已確認做法。

它不是AI交接系統，也不管理員工身分。它可以獨立使用，也能在同一工作中與交接系統協作。

## 正式資料夾結構

預設把兩個資料夾放在工作根目錄同一層：

```text
工作根目錄/
├─ 作圖系統/
├─ picture/
├─ 交接資料夾/      可選
└─ 其他工作資料/
```

- `作圖系統`保存流程、規格、候選、樣板登錄、當前契約、驗證方法與QA紀錄。
- `picture`保存原始素材、候選、未驗收、未通過、已驗收及內部作業資料。
- 更新作圖系統不會自動搬移、重驗或重建圖片。
- 實際名稱可以更改，但AI必須在工作說明中記錄唯一正式位置。

## 最簡單的使用方式

第一次：

> 找到作圖系統，執行！首次建立。先只讀分析，說明準備建立的內容，等我確認後再寫入。

開始一張圖：

> 執行！開始作圖。先建立最短充分契約，再依規格製作。

測試兩種畫法：

> 執行！測試候選。固定共同條件，分開記錄差異與證據，不要自行選正式方案。

開始批量：

> 執行！批次製作。先確認樣板、驗證方法與批次條件成立。

## 工作規格與工作方法

本工作的SOP、品牌指南與需求可以：

- 由作圖系統管理：放在`40_工作規格`。
- 保留在外部位置：在`13_工作規格與來源.md`建立引用。
- 兩種方式混合使用。

本工作專用的製作方法、工具、驗證器、回歸案例與已知問題解法放`50_工作方法`，並在`22_驗證方法登錄.md`寫明它能證明與不能證明什麼。這些內容不會混入通用核心。

臨時導入資料只在建立或遷移時使用；內容被吸收或引用後，不應繼續作為日常入口。

## QA和「通過」的差異

系統把證據狀態分成：

1. `未驗證`
2. `同源檢查通過`
3. `獨立驗證通過`
4. `等待使用者確認`
5. `使用者已確認`

如果產生圖片與驗證圖片使用同一份最終座標、遮罩、公式或判斷，只能算同源檢查，不能宣稱獨立驗證。技術驗證通過也不代表使用者已確認。

檢查強度依變動風險決定。放大觀看只是可能的工具，倍率本身不是品質證據，也不需要對每張圖固定執行所有倍率。

## 與交接系統一起使用

你可以直接要求作圖，不必先下另一條接手指令：

- 只讀查看、分析與規劃不接手。
- 第一次正式寫入前，作圖系統會自動依現有交接制度取得工作權。
- 已是目前工作者時不重複接手。
- 有其他工作者或狀態不允許時停止。
- 找不到交接系統時仍可獨立使用。

交接系統只保存作圖系統的正式入口、里程碑、阻塞與整體下一步；視覺規格、候選、樣板、逐張QA與批次統計只保存在作圖系統，避免雙重維護。

## 功能與指令

| 功能 | 明確指令 | 用途 |
|---|---|---|
| 首次建立 | `！首次建立` | 建立空白工作，或從既有規格與成果導入 |
| 開始作圖 | `！開始作圖` | 建立本張契約後開始製作 |
| 測試候選 | `！測試候選` | 分開測試尚未定案的畫法 |
| 確認樣板 | `！確認樣板` | 登錄使用者確認的樣板及範圍 |
| 批次製作 | `！批次製作` | 通過樣板、驗證及批次閘門後執行 |
| 檢查圖片 | `！檢查圖片` | 依變動風險選擇最低充分QA |
| 更新工作規格 | `！更新規格` | 修改本工作的視覺規格並評估影響 |
| 同步工作規格 | `！同步工作規格` | 核對SOP、品牌指南或需求來源 |
| 更新通用系統 | `！更新作圖系統` | 更新本套通用制度，不等於改工作風格 |
| 同步交接記憶 | `！同步交接摘要` | 同步最小里程碑與入口 |
| 查看狀態 | `！檢查狀態` | 只讀目前狀態 |

沒有指令符號時，AI仍可依自然語言判斷；有指令符號時，必須依既有功能與條件執行，條件不符不能擅自改做其他寫入功能。

## 遇到問題時會怎麼做

使用者只要指出問題或要求檢查，不必再學一條新指令。系統會：

1. 先判斷這是成果缺陷、規格變更或一般疑問。
2. 用規則索引找到可能相關的既有規則，再讀正式來源。
3. 若已有規則，優先修正沒有遵守、規則不清或驗證不足，不重複堆規則。
4. 修正成果時，同時判斷規格、方法、驗證或回歸案例是否要更新。
5. 只有完成必要回歸且證據充分，才會說「已修正」。

局部問題只停止受影響的成果或批次，不會無理由重驗全部圖片。規格變更與疑問也不會被誤記成缺陷。

## 0.5版主要差異

- 新增可重建的規則與回歸索引，遇到已知問題先定位，不必重讀所有規格。
- 新增缺陷修正閉環，要求同時處理成果、根因、必要的流程／驗證更新與回歸。
- 明確區分缺陷、規格變更與疑問，避免每次回饋都增加規則。
- 說明型標註圖可登錄「標註—目標—說明」對應；結構通過不冒充語意正確。
- 來源身分、顯示類型與成果名稱分離，降低同名來源碰撞。
- 模組狀態介面改由manifest、身分入口與當前工作三個權威來源產生，不再把全部現況誤歸給單一文件。

## 0.4版主要差異

- 作圖系統與`picture`成果區改為預設同層、彼此分離。
- 工作專用規格與方法正式納入系統管理區，但與通用核心隔離。
- `00`不再複製視覺規格、樣板、任務、階段與批次現況。
- 新增驗證方法登錄及五級證據狀態，阻止同源檢查冒充獨立驗證。
- QA由變動風險觸發，不再把固定倍率當成所有圖片的必要程序。
- 交接協作改為傳遞里程碑與入口，不重複保存作圖內部狀態。
- 新增舊容器與臨時導入資料轉成正式同層架構的通用流程。
