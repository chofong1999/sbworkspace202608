# 日常接手與交接

- 制度版本：1.12

## 原則

1. 同時只有一名員工修改正式工作。
2. 各類資訊只由`00`的入口表指定文件負責；摘要、契約與日誌不反向覆蓋權威規則或現況。
3. 未知寫`未知`；結論不得強於證據，已產出不得自動等同已完成。
4. 沒變就不重讀、不重驗、不重算。
5. 修改後依相依表核對，不做無目的全文掃描。
6. `12`只留仍有效的未完成、阻塞、待決定與必要驗證狀態。
7. 世代代表可供下一名員工正常接續的正式快照，不代表回覆數、工具數、檔案數或小成果數。

## 名詞與交接邊界

| 名詞 | 定義 | 是否自行觸發交接 |
|---|---|---|
| 模型回合 | 一次AI回覆或一段工具執行 | 否 |
| 單項成果 | 一張圖、一段程式、一節筆記或其他小成果 | 否 |
| 工作階段 | 同一員工持有工作權並連續處理同一工作，可跨多個回合與成果 | 否 |
| 工作中檢查點 | 工作階段內為降低中斷復原成本而更新的最小現況 | 否 |
| 正式交接 | 結束工作階段、形成可接續快照並釋放工作權 | 是；有正式差異時世代加一 |

「離開」只指工作階段結束，不指回覆結束、工具返回、成果已展示或暫時沒有下一個工具可呼叫。

### 正式交接觸發

符合下列任一條件才正式交接：

1. 使用者明確輸入`！交接`，或以無歧義自然語言要求本批完成後交接。
2. 使用者明確表示暫停、結束、改天繼續、準備換對話／AI，且語意包含釋放工作權。
3. 一次性自動工作在取得工作權前已明定完成後釋放，且沒有等待同一對話立即續作的互動階段。
4. 為讓另一名員工接手而必須釋放工作權。

下列情況不得單獨觸發交接：

- 一次AI回覆、工具呼叫或指令執行結束。
- 一項小成果完成或已向使用者展示成果。
- 使用者追問、補充、糾正、要求修正或開始同一工作的下一小節。
- 只有時間經過；固定逾時不能證明工作完成。

語意不明時維持`工作中`。只有是否釋放工作權會實質影響其他員工，且無法由上下文判斷時，才詢問一次。

## 接手與續作

### 同一工作者續作

`00`為`工作中`且目前工作者就是本對話的員工代號時，直接續作：

1. 不重新執行接手、不重複登記員工、不改開始時間、不增加世代。
2. 沿用已讀的`10／11／12`；只有來源可能被外部修改、記憶不可靠、出現矛盾或正式交接前才補讀必要部分。
3. 新要求仍依「繼承使用者要求」分類；同一工作階段內的多項差異最後合併交接。

`工作中`但目前工作者不是本對話時停止寫入，依異常處理核對；不得猜測自己是原工作者或因逾時奪權。

### 全新員工

讀`10／11／12`，正常時不讀舊日誌；確認成果位置存在，有現成版本值才比較。需要登記時才讀`20`並新增自己。

### 回來的舊員工

依序選擇第一個足以可靠工作的方式：

1. **零差異：** 同一對話仍可靠知道目標與下一步，且最後已讀等於最新日誌；只核對`00`。
2. **增量：** 未讀日誌通常不超過三筆且仍在活動日誌；讀未讀增量及最新版`12`。
3. **快照：** 未讀較多、已封存、日誌異常冗長或記憶不可靠；讀`10／11／12`，遇到具體疑問才查歷史。

新對話是新員工。無法準確說出目標與下一步時不得用零差異；不要先讀完大量日誌才改選快照。

### 開始寫入

1. 只有`可接續`能由無工作權開始；寫入前重讀`00`，狀態或世代變更就停止。
2. 新員工登記；舊員工只在最後已讀落後時更新。
3. 只在`00`填目前工作者、開始時間並改為`工作中`。
4. 不寫開始日誌、不更新使用者摘要、不增加世代。

外部子系統可在第一次正式寫入前自動執行以上步驟；只讀與同一工作者續作時不重複。

## 繼承與修改使用者規則

- 長期要求寫`11`並使用未曾用過的下一個`RULE-ID`；本輪或單一成果指示寫`12`。
- 依適用範圍、能否偏離及是否為驗收條件分成`必須／禁止／一般／偏好`；不單靠語氣詞。
- 相似說法不自動升降級。偏好頻率只在使用者對實際結果表示過多、過少、增加或減少時改。
- 重要但無法判斷是特例或長期變更時只詢問一次；未回答就原文放`12`待決定。
- 改寫規則內容時保留原`RULE-ID`；刪除後ID不重用。拆分或合併須在規則的`取代關係`連結舊ID。
- `！查看規則`只從`11`即時整理，不接手、不另存規則清單。無參數預設列出全部現行規則；可依`全部／強制／一般／偏好／RULE-ID／關鍵字`篩選。精簡輸出至少包含ID、強度、範圍與一句規則內容；展開單一規則時，有填寫原意、AI理解或常見誤解就一併顯示。
- `！修改規則 RULE-ID <內容>`是正式寫入。修改前重述舊規則、新規則與影響範圍；存在兩種實質解讀時先詢問一次。未知ID停止並列最接近候選，不自行新建。
- 修改後核對`12`臨時要求、被引用的契約、使用者摘要及現役文件中的RULE-ID引用；舊意思不得留成第二權威。

## 任務風險、執行契約與完成閘門

### 風險分級

| 級別 | 判定 | 最低處理 |
|---|---|---|
| R0 | 純讀取、低風險、可立即核對 | 原有最低檢查 |
| R1 | 單檔、可逆、規則清楚 | 確認輸入與輸出位置 |
| R2 | 多檔、批次、外部資料、工具依賴或曾失敗 | 能力預檢；只讀適用契約 |
| R3 | 不可逆、權限敏感、高風險或難復原 | 完整預檢；必要時先詢問或停止 |

風險級別只決定檢查深度，不取代使用者授權或安全限制。`！能力檢查`是只讀診斷，輸出任務風險、必要能力／輸入／工具、已證明能力、缺口、最小試作、停止條件與建議狀態；模型自述不算證據。

### 執行契約

- `11`是規則內容、強度與範圍的唯一權威；需要契約時只引用`CONTRACT-ID`。
- `80_按需/15_規則執行契約.md`只保存被規則引用的操作欄位，不重述或改寫規則。
- 只有適用的R2／R3任務，或規則明確要求時才讀相關契約；R0／R1不讀全部契約。
- 契約缺失、引用不存在或與`11`矛盾時停止完成宣告，回到權威規則修正；不得由契約覆蓋規則。
- `missing_behavior`不得只寫「自行判斷」。允許降級時要列出可保留的狀態與不得宣稱的內容。

### 完成宣告閘門

`12`的成果狀態只使用：`已完成`、`已產出未驗證`、`部分完成`、`驗證未通過`、`受阻`、`無法可靠完成`。

宣稱`已完成`前必須：

1. 列出本任務適用的強制規則；逐項具備通過證據、明確不適用，或使用者明示授權的降級結果。
2. 有契約者依`validator`取得`pass_evidence`；必要輸入缺少時依`missing_behavior`處理。
3. 核對實際成果、驗證結果與完成宣告一致。看過規則、已嘗試、已產出或表面正常都不等於通過。
4. 無法通過時使用其他標準狀態並保留下一步，不得用較模糊措辭暗示完成。

正常情況不保存全部PASS流水帳；`12`只留當前必要摘要，詳細證據放成果或既有驗收紀錄。失敗、未驗證與重大里程碑才展開。

## 工作中檢查點

目前工作者只在重要里程碑、後續復原成本明顯升高或進入高風險修改前，更新`12`的「工作中檢查點」：

1. 只寫已完成、未驗證、下一步與必要成果入口。
2. 保持`工作中`、原工作者、原開始時間、原最新日誌與原世代。
3. 不追加`30`、不更新最近成功交接時間，不同步`20`或使用者摘要，除非其權威欄位本身真的改變。
4. 回覆結束或每個小成果完成不得自動建立檢查點；依中斷後重建成本判斷，不採固定分鐘或回合數。
5. 檢查點是復原證據之一，不是成功交接；意外中斷後仍須核對實際成果。

## 正式交接

1. 保存成果，只驗證本工作階段的變動。
2. 長期背景或規則有變才改`10／11`；核對相關RULE-ID與契約引用。
3. 更新`12`，移除已完成或解除項；正式快照取代工作中檢查點的暫時內容。
4. 把同一工作階段的有效差異合併成`30`的一筆短日誌；不得按回覆或小成果拆成多代。
5. 執行完成閘門、最低交接檢查及本輪相依核對。
6. 通過後取得完成時間，一次更新日誌、執行員工、使用者摘要及`00`；世代加一，清空工作者與開始時間，最後改為`可接續`。

若成果、正式情報、要求、決定與異常狀態都沒變但需要釋放工作權，不新增日誌或世代，也不改最近成功交接時間；只清空工作者並恢復`可接續`。新員工登記可保留。

### 最低交接檢查

- 本次符合正式交接觸發，不是只因回覆、工具或小成果結束。
- 同一工作階段只有一筆合併差異日誌與至多一個新世代。
- `12`的成果狀態、結果、未完成與下一步相容，無已解除待辦。
- `已完成`事項已通過適用強制規則與契約；未驗證成果沒有寫成完成。
- 已存在成果不得寫成未產生；下一步必須接續最新完成事實。
- `00`最新／下一日誌與新增日誌連續。
- 執行員工最後已讀與交接時間已更新。
- `00`工作者與開始時間已清空，最後為`可接續`。
- 使用者摘要不與`00／10／12`的完成快照衝突。
- 本輪修改文件的引用、RULE-ID、CONTRACT-ID與必要版本正確。
- 同一外部子系統只有一個現役入口；舊入口只留在歷史或禁止使用區。

全文搜尋、完整雜湊、全員工核對、歷史全文、成果全面驗收及封存掃描，只在出現差異、異常、版本升級、廣泛重寫或使用者要求時進行。

| 背景、成果位置、完成條件 | `10` | `12`引用、使用者摘要 |
| 長期規則、強度、RULE-ID | `11` | `12`臨時要求、契約引用、規則引用 |

| 子系統里程碑 | 子系統 | `12`最短摘要 |

未列出的文件不因「保險起見」重寫；只有權威或控制流程本身改變時才完整檢查現役制度檔。

## 成果、日誌與回饋

- 正常接手只確認成果位置、必要入口與現成版本值；不為證明未變而重算。
- 本輪修改、版本不同、`11`要求、最終驗收或使用者要求時才深入；修改成果只查變動項。
- 路徑、大小、時間相同只能表示未發現中繼資料差異，不能宣稱內容相同。
- 開始、續作、正常接手、只查看、能力檢查、處理建議、工作中檢查點與回饋檔不寫工作日誌或增加世代。
- 日誌只追加；更正用新日誌引用舊編號。
- `回饋與問題_待交付`不是權威資料，正常接手與交接不讀內容。
