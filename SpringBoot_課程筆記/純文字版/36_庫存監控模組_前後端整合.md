# Spring Boot 學習筆記 36：庫存監控模組前後端整合

- 後端範例：`inventory-api`
- 前端範例：`invetory-react`（資料夾沿用課堂拼字，套件名稱是 `inventory-react`）
- 資料庫：MySQL `classicmodels`
- 學習目標：把既有資料表、統計 Query、統一 API 回應與 React 儀表板組成完整模組

## 本章新增語法快速表

| 想完成的事情 | 寫法 |
|---|---|
| 讓查詢方法預設為唯讀交易 | `@Transactional(readOnly = true)` |
| 寫入方法覆寫為可寫交易 | 方法上的 `@Transactional` |
| 將統計 Query 結果轉成 DTO | `List<Object[]>` → `StockSummaryDTO` |
| 統一成功回應 | `ApiResponse.ok(data)` |
| 建立 Axios 共用實例 | `axios.create({ baseURL })` |
| 同時載入兩組資料 | `Promise.all([...])` |
| TypeScript 定義回應形狀 | `interface Product`、`ApiResponse<T>` |
| 建立多頁前端 | `Routes`、`Route`、`NavLink` |

## 1. 模組架構

```text
React + TypeScript（localhost:3000）
        │ Axios / JSON
        ▼
Spring Boot REST API（localhost:8080）
        │ JPA / Hibernate
        ▼
MySQL classicmodels
  ├─ products            既有產品資料
  └─ stock_thresholds    各產品安全水位
```

本章不是只做一支 CRUD API，而是把資料查詢、統計、低庫存規則、統一回應、前端 Service 與多頁畫面放到同一個功能模組。

## 2. 準備資料庫

`application.properties`：

```properties
server.port=8080

spring.datasource.url=jdbc:mysql://localhost:3306/classicmodels?useSSL=false&serverTimezone=Asia/Taipei&characterEncoding=UTF-8
spring.datasource.username=root
spring.datasource.password=1234

spring.jpa.hibernate.ddl-auto=validate
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
spring.jpa.hibernate.naming.physical-strategy=org.hibernate.boot.model.naming.PhysicalNamingStrategyStandardImpl
```

使用 `validate` 時，資料表必須先存在。先在 `classicmodels` 執行：

```sql
CREATE TABLE IF NOT EXISTS stock_thresholds (
    id               INT         NOT NULL AUTO_INCREMENT PRIMARY KEY,
    product_code     VARCHAR(15) NOT NULL UNIQUE,
    min_quantity     INT         NOT NULL DEFAULT 200,
    reorder_quantity INT         NOT NULL DEFAULT 500,
    updated_at       DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP
                               ON UPDATE CURRENT_TIMESTAMP,
    CONSTRAINT fk_threshold_product
        FOREIGN KEY (product_code) REFERENCES products(productCode)
        ON DELETE CASCADE
);
```

若本機密碼不是 `1234`，必須改成自己的 MySQL 密碼。

## 3. Entity 對應既有欄位

`Product` 的主鍵不是數字自動編號，而是 `productCode`：

```java
@Entity
@Table(name = "products")
@Data
public class Product {

    @Id
    @Column(name = "productCode", length = 15)
    private String productCode;

    @Column(name = "quantityInStock", nullable = false)
    private short quantityInStock;

    @Column(name = "MSRP", nullable = false)
    private double msrp;
}
```

`StockThreshold` 保存每個產品的安全水位，並在新增或更新時記錄時間：

```java
@PrePersist
@PreUpdate
public void onUpdate() {
    updatedAt = LocalDateTime.now();
}
```

## 4. Repository 查詢

一般篩選可使用 Derived Query：

```java
List<Product> findByProductLine(String productLine);
List<Product> findByProductVendor(String productVendor);
```

儀表板依產品線統計：

```java
@Query("""
    SELECT p.productLine,
           SUM(p.quantityInStock),
           COUNT(p),
           MIN(p.quantityInStock)
    FROM Product p
    GROUP BY p.productLine
    ORDER BY SUM(p.quantityInStock) DESC
    """)
List<Object[]> getStockSummaryByProductLine();
```

回傳的每一列是 `Object[]`，Service 必須依 SELECT 欄位順序轉型：

```java
return productRepo.getStockSummaryByProductLine()
    .stream()
    .map(row -> new StockSummaryDTO(
        (String) row[0],
        ((Number) row[1]).longValue(),
        ((Number) row[2]).longValue(),
        ((Number) row[3]).intValue()
    ))
    .toList();
```

## 5. Service 交易邊界

```java
@Service
@Transactional(readOnly = true)
public class ProductService {

    public List<Product> findAll() {
        return productRepo.findAll();
    }

    @Transactional
    public Product create(ProductDTO dto) {
        if (productRepo.existsById(dto.getProductCode())) {
            throw new IllegalArgumentException("Product code already exists");
        }
        return productRepo.save(mapToEntity(dto));
    }
}
```

類別層的 `readOnly = true` 適用查詢；新增、更新、刪除方法再用方法層的 `@Transactional` 覆寫，讓寫入交易清楚集中在 Service。

安全水位採 Upsert：有資料就修改，沒有就建立。

```java
StockThreshold threshold = thresholdRepo.findByProductCode(productCode)
    .orElse(new StockThreshold());

threshold.setProductCode(productCode);
threshold.setMinQuantity(minQty);
threshold.setReorderQuantity(reorderQty);
return thresholdRepo.save(threshold);
```

## 6. 統一 API 回應

```java
public class ApiResponse<T> {
    private boolean success;
    private String message;
    private T data;

    public static <T> ApiResponse<T> ok(T data) {
        ApiResponse<T> response = new ApiResponse<>();
        response.success = true;
        response.message = "success";
        response.data = data;
        return response;
    }
}
```

Controller 回傳：

```java
return ResponseEntity.ok(ApiResponse.ok(productService.findAll()));
```

JSON 形狀固定為：

```json
{
  "success": true,
  "message": "success",
  "data": []
}
```

## 7. API 清單

| Method | URL | 功能 |
|---|---|---|
| GET | `/api/products` | 全部商品，可用 `productLine`、`vendor`、`keyword` 篩選 |
| GET | `/api/products/{productCode}` | 單一商品 |
| POST | `/api/products` | 新增商品 |
| PUT | `/api/products/{productCode}` | 更新商品 |
| DELETE | `/api/products/{productCode}` | 刪除商品 |
| GET | `/api/products/low-stock` | 低庫存商品 |
| GET | `/api/products/dashboard/summary` | 各產品線統計 |

| GET | `/api/products/filter/vendors` | 不重複供應商 |
| GET | `/api/thresholds/{productCode}` | 查詢安全水位 |
| PUT | `/api/thresholds/{productCode}` | 新增或更新安全水位 |

## 8. React Service 層

前端不要讓每個頁面重複寫完整 URL 與回應解包：

```typescript
const api = axios.create({
  baseURL: 'http://localhost:8080/api'
})

async function unwrap<T>(
  promise: Promise<{ data: ApiResponse<T> }>
): Promise<T> {
  const response = await promise
  return response.data.data
}

export function getProducts(): Promise<Product[]> {
  return unwrap<Product[]>(api.get('/products'))
}
```

頁面只需呼叫具名函式，不直接處理後端包裝格式。

## 9. 前端路由與頁面

```tsx
<Routes>
  <Route path="/" element={<Navigate to="/dashboard" replace />} />
  <Route path="/dashboard" element={<Dashboard />} />
  <Route path="/products" element={<ProductList />} />
  <Route path="/products/:id" element={<ProductDetail />} />
  <Route path="/low-stock" element={<LowStockAlert />} />
</Routes>
```

- `Dashboard`：以 `Promise.all()` 同時載入統計與低庫存資料。
- `ProductList`：查詢、產品線與供應商篩選。
- `ProductDetail`：以 `useParams()` 取得產品代碼。
- `LowStockAlert`：讀取及修改每個產品的安全水位。

React Router 的完整語法與導覽行為集中在[第38章](38_React_Router導覽_動態路由與404.md)。

## 11. 範例限制與檢查點

- CORS 範例允許 `http://localhost:3000`，若改用 Vite 5173，後端也要加入該來源。
- `ddl-auto=validate` 不會替讀者建立 `stock_thresholds`；SQL 必須先執行。
- 課堂低庫存 JPQL 的註解表示「沒有安全水位時使用 200」，但目前子查詢沒有資料時可能得到 `null` 而不會套用預設值。要保證所有產品都有預設規則，應先建立每項產品的 threshold，或另寫能處理無關聯資料的 Query。
- 前端使用 Create React App、TypeScript、Axios 與 React Router；它和前面 Vite JavaScript 範例的建置指令不同。
