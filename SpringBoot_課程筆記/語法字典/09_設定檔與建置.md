<a id="basic-properties"></a>
## 基本`application.properties`

```properties
spring.application.name=demo
server.port=8080
```

Properties格式是`key=value`。`#`開頭為註解。相同key重複出現時容易造成閱讀與覆蓋混亂，應只保留真正生效的一份。

<a id="database-properties"></a>
## DataSource與JPA

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/shop_db
spring.datasource.username=root
spring.datasource.password=1234
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver

spring.jpa.hibernate.ddl-auto=validate
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```

| 設定 | 用途 | 注意 |
|---|---|---|
| `spring.datasource.url` | JDBC連線網址 | 不同資料庫格式不同 |
| `username`／`password` | 資料庫帳密 | 部署時改用環境變數，不要把正式密碼提交Git |
| `driver-class-name` | JDBC Driver類別 | 多數情況可由URL與依賴推導；課程可明寫便於辨識 |
| `spring.jpa.hibernate.ddl-auto` | Schema動作 | 常見`none`、`validate`、`update`、`create`、`create-drop` |
| `spring.jpa.show-sql` | 顯示SQL | 開發除錯使用 |
| `spring.jpa.properties.hibernate.format_sql` | 排版SQL | 只影響輸出可讀性 |
| `spring.jpa.database-platform` | 指定Hibernate Dialect | 無法正確推導或特殊資料庫時使用 |

`ddl-auto`選擇：

| 值 | 行為 | 適合情境 |
|---|---|---|
| `validate` | 只檢查Entity與Schema是否相容 | 已有資料表、不可讓程式改表 |
| `update` | 嘗試增量調整Schema | 本機練習；不可視為正式migration工具 |
| `create` | 啟動時重建 | 可丟棄資料的測試環境 |
| `create-drop` | 啟動建立、關閉刪除 | 自動化測試／暫存練習 |
| `none` | 不處理Schema | 完全由migration或SQL管理 |

### SQLite範例

```properties
spring.datasource.url=jdbc:sqlite:shop.db
spring.datasource.driver-class-name=org.sqlite.JDBC
spring.jpa.database-platform=org.hibernate.community.dialect.SQLiteDialect
```

SQLite檔案相對路徑以應用程式的工作目錄為基準；本機與容器的工作目錄不同時，資料庫檔位置也不同。

<a id="sql-init"></a>
## SQL初始化

```properties
spring.sql.init.mode=always
spring.sql.init.schema-locations=classpath:schema.sql
spring.sql.init.data-locations=classpath:data.sql
spring.jpa.defer-datasource-initialization=true
```

| 設定 | 定義 |
|---|---|
| `spring.sql.init.mode` | `always`強制初始化；`never`停用；其他行為依版本與資料庫類型而定 |
| `schema-locations` | 建表SQL資源位置 |
| `data-locations` | 初始資料SQL資源位置 |
| `defer-datasource-initialization` | 讓JPA初始化後才執行SQL script；是否需要取決於Schema由誰建立 |

不要同時讓`ddl-auto=create`、`schema.sql`和外部migration互相競爭建立同一批表。

<a id="environment-variables"></a>
## 環境變數佔位

```properties
server.port=${PORT:8080}
spring.datasource.url=${DATABASE_URL:jdbc:sqlite:shop.db}
```

`${PORT:8080}`在Spring設定檔中表示：有`PORT`環境變數就使用它，否則使用`8080`。這不是Thymeleaf的`${...}`；兩者只是在不同語境中使用相似符號。

<a id="maven-goals"></a>
## Maven常用Goal

在含`pom.xml`的專案根目錄執行：

```bash
mvn spring-boot:run
mvn test
mvn clean package
mvn clean install
```

| 指令 | 結果 |
|---|---|
| `spring-boot:run` | 直接啟動Spring Boot應用程式 |
| `test` | 執行測試 |
| `clean` | 刪除先前的`target/`建置產物 |
| `package` | 編譯、測試並產生JAR／WAR |
| `install` | 在package後把成品放入本機Maven repository |

打包後執行：

```bash
java -jar target/專案名稱-版本.jar
```

若使用Maven Wrapper，Windows可改用`mvnw.cmd`，使專案依wrapper指定版本執行，不要求系統另裝相同Maven版本。

<a id="pom-dependencies"></a>
## `pom.xml`依賴判讀

```xml
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
```

- `groupId`：組織／套件群識別。
- `artifactId`：實際模組名稱。
- `version`：Spring Boot管理的常見依賴通常不必個別填；由父POM／BOM統一管理。
- `scope`：例如`test`只在測試階段使用、`runtime`主要在執行期需要。

不要只複製Java註解；對應starter、JDBC driver或第三方依賴也必須存在，程式才可編譯與執行。
